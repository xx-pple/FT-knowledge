# 类型与转换

类型转换的核心问题是：什么时候语言会悄悄帮你转，什么时候宁可报错也不转。

## 是什么 {#what}

弱类型语言在做运算和比较时，会按照一套固定规则把操作数转成同一类型。这套规则本身是确定的，只是不符合直觉——所以绝大多数「诡异」的 bug 都来自这里。

JavaScript 有七种原始类型：`undefined`、`null`、`boolean`、`number`、`string`、`symbol`、`bigint`，其余都是对象。

## 隐式转换发生在哪 {#implicit}

三个高频场景：

```js
1 + '1'          // '11'      数字被转成字符串
'5' * '2'        // 10        字符串被转成数字
[] + {}          // '[object Object]'
0 == ''          // true
null == undefined // true
NaN === NaN      // false
```

规律可以归纳成两条：

1. **`+` 只要有一侧是字符串，就走字符串拼接**；否则走数字加法。
2. **`==` 会先做类型转换再比较**，`===` 不会。

## 显式转换 {#explicit}

| 目标 | 写法 | 注意 |
|---|---|---|
| 数字 | `Number(x)` | 遇到非数字字符直接 `NaN` |
| 数字 | `parseInt(x, 10)` | 从左往右解析，遇到非法字符停止 |
| 字符串 | `String(x)` | 任何值都能转，不会抛错 |
| 布尔 | `Boolean(x)` | `0`、`''`、`null`、`undefined`、`NaN` 为假，其余为真 |

两者最容易混淆的地方：

```js
Number('12px')    // NaN
parseInt('12px')  // 12

Number('')        // 0
parseInt('')      // NaN
```

需要严格校验用户输入时用 `Number`，需要「能读多少读多少」时用 `parseInt`。

::: warning 别省掉基数
`parseInt('08')` 在极老的引擎里会被当成八进制。现代引擎已修正，但显式写 `parseInt(x, 10)` 仍是好习惯。
:::

## 常见错误 {#pitfalls}

**用 `==` 比较**。`0 == ''`、`0 == '0'`、`false == '0'` 全是 `true`。除了 `x == null` 这种「同时判断 null 和 undefined」的惯用法，其余一律用 `===`。

**`typeof null` 返回 `'object'`**。这是 1995 年的实现遗留，永远无法修复。判断 null 要用 `x === null`。

**数组的 `+`**。`[1, 2] + [3]` 得到 `'1,23'`，因为数组先被转成字符串。

**浮点数比较**。`0.1 + 0.2 === 0.3` 是 `false`。这不是 JavaScript 的问题，是 IEEE 754 的固有行为，改用误差范围比较。
