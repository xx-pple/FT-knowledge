# 二分查找

在有序且支持随机访问的序列里，每次把查找范围缩小一半，从而在 $O(\log n)$ 时间内定位目标。

## 前提 {#prerequisites}

两个条件缺一不可：

1. **序列有序**（单调）。无序数据先排序再二分，整体是 $O(n \log n)$，通常不如直接线性扫描。
2. **支持随机访问**。这排除了链表——这就是 [链表](../ds/1.linked-list.md) 里那张表的直接推论。

![二分查找：目标 7，区间从 [0,7] 收敛到 [5,6]，两次比较后命中](./assets/binary-search.svg)

## 复杂度 {#complexity}

每次迭代把问题规模减半，递推式：

$$T(n) = T\left(\frac{n}{2}\right) + O(1) = O(\log n)$$

空间复杂度 $O(1)$（迭代写法）。

## 模板 {#template}

左闭右闭区间 `[left, right]`，这个写法最好记，因为循环条件和边界更新是一致的：

```js
function binarySearch(nums, target) {
  let left = 0
  let right = nums.length - 1

  while (left <= right) {
    const mid = left + ((right - left) >> 1)
    if (nums[mid] === target) return mid
    if (nums[mid] < target) left = mid + 1
    else right = mid - 1
  }

  return -1
}
```

三个细节值得单独记：

| 细节 | 写法 | 原因 |
|---|---|---|
| 循环条件 | `left <= right` | 闭区间，`left === right` 时还有一个元素待查 |
| 中点计算 | `left + ((right - left) >> 1)` | 避免 `left + right` 溢出 |
| 边界更新 | `mid + 1` / `mid - 1` | `mid` 已比较过，必须排除，否则死循环 |

## 常见错误 {#pitfalls}

**死循环**。把 `left = mid` 而不是 `mid + 1`，当 `left` 和 `right` 相邻时 `mid` 恒等于 `left`，区间永不缩小。

**区间开闭混用**。左闭右闭配 `left < right`，或者左闭右开配 `mid - 1`，都会漏掉元素。选一种写法，全程一致。

**找「第一个满足条件的位置」时直接套模板**。这类问题（如「第一个大于等于 target 的下标」）需要变形，标准模板返回的是「任意一个匹配位置」，不保证是最左的。

**在浮点数上直接判等**。实数二分要改成迭代固定次数，或者用 `right - left > eps` 作为终止条件。

::: tip 记忆口诀
闭区间配 `<=`，更新必带 `±1`。这两句话能挡掉九成的实现错误。
:::
