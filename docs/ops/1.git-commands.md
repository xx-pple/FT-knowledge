# Git 常用命令

按「我想干什么」组织，而不是按命令字母序。适用 Git 2.23 及以上（`restore` / `switch` 拆分之后）。

## 我改坏了，想撤销 {#undo}

先分清三种情况，选错了会丢代码：

| 场景 | 命令 | 后果 |
|---|---|---|
| 工作区改了，没 add | `git restore <file>` | 丢弃未暂存的修改，**不可恢复** |
| 已 add，没 commit | `git restore --staged <file>` | 只从暂存区撤下，改动还在 |
| 已 commit，没 push | `git reset --soft HEAD~1` | 撤销提交，改动保留在暂存区 |
| 已 push 到公共分支 | `git revert <commit>` | 生成一个反向提交，历史保留 |

::: danger soft / mixed / hard 的区别
`--soft` 只移动 HEAD，改动留在暂存区；`--mixed`（默认）移动 HEAD 并清空暂存区，改动留在工作区；`--hard` 三处全清，**未提交的改动直接消失**。用 `--hard` 前先 `git stash`。
:::

## 分支操作 {#branch}

```bash
git switch -c feature/x        # 新建并切换（替代 checkout -b）
git switch main                # 切回
git branch -d feature/x        # 删除已合并分支
git branch -D feature/x        # 强制删除未合并分支

git rebase main                # 把当前分支的提交搬到 main 之上
git merge --no-ff feature/x    # 保留分支信息的合并
```

`rebase` 会重写提交哈希，**只能用于还没推送的本地提交**。已经推送的分支用 `merge`。

## 排查 {#debug}

| 我想知道 | 命令 |
|---|---|
| 这行代码是谁改的 | `git blame -L 10,20 <file>` |
| 某个文件什么时候被删的 | `git log --diff-filter=D --name-only -- <path>` |
| 两个分支差了什么 | `git log --oneline main..feature/x` |
| 这次提交改了哪些文件 | `git show --stat <commit>` |
| 谁改动了这个字符串 | `git log -S'searchString' --oneline` |
| 本地和远程的差异 | `git status -sb` |

## 清理 {#cleanup}

```bash
git remote prune origin        # 清掉远程已删除分支的本地引用
git gc --prune=now             # 手动触发垃圾回收
git clean -nd                  # 预览会被删除的未跟踪文件（先看再删）
git clean -fd                  # 真正删除未跟踪文件，不可恢复
```

⚠️ `git clean -fd` 会删掉所有未跟踪文件，包括你刚写好但还没 `git add` 的草稿。执行前一定先跑 `-nd` 看一眼。

## 常见错误 {#pitfalls}

**用 `git add .` 一把梭**。会把 `node_modules`、构建产物、临时文件一起提交。先配好 `.gitignore`，再用 `git add -A` 前看一眼 `git status`。

**在公共分支上 rebase**。别人基于旧提交的工作会全部错乱。公共分支只 merge，不 rebase。

**`git push -f` 救场**。强推会覆盖远程历史，如果别人已经拉取过，他们的本地仓库会进入难以修复的状态。除非确认只有你一个人在用这个分支。

**忽略 `.gitignore` 已经提交过的文件**。`.gitignore` 只对未跟踪文件生效。已经提交的文件要先 `git rm --cached <file>` 才会被忽略。
