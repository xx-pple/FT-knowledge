# 写作与发布教程

从打开编辑器到线上能看到，完整走一遍。跟着做就行，每一行命令都能直接复制。

## 第 0 步：准备环境 {#setup}

只需要装一次。

**Node.js 18 以上**。检查：

```bash
node -v
```

版本低于 18 就去 nodejs.org 装新版。

**拿到项目并装依赖**：

```bash
cd /d/PROJECTS/NOTE
npm install
```

`node_modules` 只需要装一次，之后不用重复。

**编辑器**。推荐 Typora（所见即所得，配图方便），VS Code 也行。用 Typora 的话先做第 5 步里的图片设置，否则后面图片路径会乱。

## 第 1 步：决定文章放哪个目录 {#directory}

分类由 `docs/` 下的目录决定，当前有 12 个，完整列表看顶部导航或首页卡片。举几个例子：

| 目录 | 放什么 |
|---|---|
| `docs/frontend/` | 前端：HTML、CSS、Vue |
| `docs/mysql/` | MySQL：关系模型、常用命令、工作流 |
| `docs/file-extension/` | 文件格式：JSON、YAML 的语法速查 |
| `docs/archive/` | 归档：从早期博客迁移的旧文，只读不改 |

**判断方法**：想一下半年后你会去哪儿找它。找不到合适的地方，就说明该开新分类了。

### 新建一个分类

**不需要改任何配置文件。** 只有三步：建目录、写 `index.md`、开始写文章。

```bash
mkdir -p docs/network
```

`docs/network/index.md` 的内容：

```md
---
title: 计算机网络
description: 协议、分层、排错
order: 3
---

# 计算机网络

协议、分层、排错。

## 本分类条目

| 条目 | 一句话 |
|---|---|
| [TCP 握手](./1.tcp.md) | 三次握手为什么是三次 |
```

frontmatter 三个字段的作用：

| 字段 | 用在哪 |
|---|---|
| `title` | 顶部导航文字、侧边栏分组名、首页卡片标题 |
| `description` | 首页卡片的副标题 |
| `order` | 排第几位，数字小的在前；省略则按目录名排在后面 |

保存后跑一次 `npm run docs:dev`，导航、侧边栏、首页卡片会同时出现这个新分类。**整个过程不碰 `config.mts`。**

::: warning order 不要重复
两个分类用同一个 `order` 时会退化成按目录名字母序排列，看起来像「排序失效」。新增分类时挑一个没被占用的数字。
:::

同理，删掉一个分类目录，导航和卡片会自动消失——但记得先搜一遍有没有别的文章链接到它，否则构建会报死链。

## 第 2 步：新建文件 {#newfile}

在分类目录下建 `.md` 文件，文件名决定三件事：URL、排序、以及是否能在 Linux 上正常访问。

```
docs/frontend/4.async.md
              ↑ ↑
              │ └── 名字部分：决定 URL，全小写英文
              └──── 数字前缀：决定侧边栏里的顺序
```

规则：

| 规则 | 正确 | 错误 | 原因 |
|---|---|---|---|
| 全小写 | `4.async.md` | `3.Async.md` | Windows 不区分大小写，Linux 区分，线上会 404 |
| 英文 | `4.async.md` | `3.异步.md` | URL 会编码成 `%E5%BC%82%E6%AD%A5`，没法分享 |
| 用中划线 | `3.event-loop.md` | `3.event loop.md` | 空格在 URL 里会变成 `%20` |
| 数字前缀 | `4.async.md` | `async.md` | 没有前缀就只能按字母序排，顺序不可控 |

数字前缀在侧边栏里会被自动去掉，只影响排序，不显示给读者。

## 第 3 步：写头部和标题 {#frontmatter}

每个文件开头必须有这一段：

```md
---
title: 异步
tags: [js, 并发]
---

# 异步

异步是指不阻塞当前执行流、把结果推迟到将来某个时刻交付的编程模型。

## 是什么 {#what}
```

四个部分，每个都有用：

**`---` 包起来的 frontmatter**：给构建器和搜索用的元数据。`title` 用于浏览器标签和搜索结果，`tags` 是给你自己分类用的。不写也能构建，但建议写。

**`# 异步`**：一级标题。它决定三件事——侧边栏里显示的菜单名、页面的大标题、搜索结果的标题。

::: warning 一级标题的硬性要求
每篇**只能有一个 `#`**。多个一级标题会让锚点重复、右侧目录错乱、搜索标题混淆。

顺便注意：VitePress 的约定是「标题写在正文里」，而不是只写在 frontmatter。OI Wiki 那种「正文不写标题」是 MkDocs 的规矩，别混用。
:::

**第一段正文**：搜索结果的摘要抓的就是这段。所以第一句要写成能独立看懂的定义，不要写「本文将介绍……」。

**`## 是什么 {#what}`**：二级标题加显式锚点。`{#what}` 是可选的，但强烈建议给需要长期引用的标题加上——不加的话，锚点由标题文本生成，你哪天把「是什么」改成「定义」，所有指向 `#是什么` 的外链就断了。

## 第 4 步：写正文 {#body}

### 标题层级

```
# 页面标题    ← 一篇只有一个
## 一级小节
### 二级小节
#### 三级小节  ← 一般不进右侧目录
```

不要跳级（`##` 直接到 `####`），右侧目录会显示得很奇怪。右侧目录默认只收录 `##` 和 `###`。

### 常用语法

**加粗和斜体**

```md
**加粗**  *斜体*  `行内代码`
```

**列表**

```md
- 无序项
- 另一项
  - 缩进两个空格变成子项

1. 有序项
2. 第二项
```

**表格**。第二行是分隔线，`:` 控制对齐：

```md
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| a | b | c |
```

**引用**

```md
> 这是一段引用
```

**分隔线**

```md
---
```

### 提示块

四种预设样式，用来强调内容：

```md
::: tip 提示
正文内容
:::

::: warning 警告
正文内容
:::

::: danger 危险
正文内容
:::

::: details 点击展开
默认折叠的内容
:::
```

不写标题就用默认文字（提示 / 警告 / 危险 / 详细信息）。这些默认文字已经在配置里中文化了。

::: warning 别把关键结论放进 details
折叠块在别的工具里可能直接摊开、也可能整块丢失。重要内容放正文。
:::

### 代码块

三个反引号加语言名，自动语法高亮：

````md
```js
const a = 1
```
````

**行号**已经在配置里全局开了。**行高亮**用花括号指定行号：

````md
```js {1,3-4}
第一行会被高亮
第二行
第三行也被高亮
第四行也被高亮
```
````

**代码分组**（多语言对比时用）：

````md
::: code-group

```js [JavaScript]
const a = 1
```

```python [Python]
a = 1
```

:::
````

### 数学公式

行内用单个 `$`，独立成行用 `$$`：

```md
时间复杂度是 $O(\log n)$。

$$
T(n) = T\left(\frac{n}{2}\right) + O(1) = O(\log n)
$$
```

独立公式的 `$$` **必须单独占一行，两侧留空行**，否则不会渲染。

## 第 5 步：插入图片 {#images}

这一步最容易出问题，仔细看。

### 先配置 Typora（只需一次）

打开 Typora：**文件 → 偏好设置 → 图像**

1. 「插入图片时」下拉框选 **复制图片到 ./${filename}.assets 文件夹**
2. 勾选 **优先使用相对路径**
3. 下面「对本地位置的图片应用上述规则」也选上

配完之后，你在 `docs/frontend/4.async.md` 里粘贴一张图，Typora 会自动：

- 创建目录 `docs/frontend/4.async.assets/`
- 把图片存进去
- 在 Markdown 里插入 `![](./4.async.assets/xxx.png)`

::: danger 不要选 ./${filename}（没有 .assets）
那个选项会把图片放进和文章同名的目录 `docs/frontend/4.async/`。功能上能用，但这样占掉了同名目录，这篇文章以后就不能有 `4.async/index.md`——两者会抢同一个路由。
:::

### 手动放图也可以

不用 Typora 的话，自己建目录、拷图片、手写路径，效果一样：

```
docs/frontend/
├─ 4.async.md
└─ assets/
   └─ event-loop.svg
```

```md
![事件循环的三个阶段](./assets/event-loop.svg)
```

### 路径规则

**唯一正确的写法是相对路径**，以 `./` 或 `../` 开头：

```md
![图](./assets/a.png)          ← 同目录下的 assets
![图](../ds/assets/b.png)      ← 上一级再进 ds
```

**不要用 `/` 开头**。`![](/images/a.png)` 会被解析成站点根目录，只有放在 `docs/public/` 下的文件才适用这种写法。文章配图放 `public` 有三个坏处：不压缩、不加哈希、文件不存在也不报错（你会到线上才发现图裂了）。

### 图片文件名

和文章文件名同样的规矩：**全小写、英文、中划线**。

`事件循环.png` 改成 `event-loop.png`。

### 压缩（重要）

GitHub Pages 有 1 GB 的站点上限，图片是唯一会撑爆它的东西。

- 截图工具直接输出 **WebP**，宽度不超过 **1600px**
- 不要贴 4K 全屏截图，缩到正文宽度后多出来的像素纯属浪费

按这个标准，300 KB 一张图能存两千多张；不压缩的话，800 KB 的 PNG 截图存到八九百张就到顶了。

::: danger 删图不会让仓库变小
Git 保留每个文件的全部历史版本。`git rm` 掉一张大图再提交，仓库体积一点都不会减。要真正瘦身只能重写 git 历史，那是破坏性操作。

**所以压缩必须在入库之前做，不能等以后清理。**
:::

### 验证

写完后跑一次构建，图片路径错会直接报错：

```bash
npm run docs:build
```

## 第 6 步：添加链接 {#links}

### 站内链接

**必须带 `.md` 后缀**：

```md
[闭包](./2.closure.md)
[链表](../git/git-cheatsheet.md)
[回到语言基础](../frontend/index.md)
[回到分类首页](../frontend/)
```

构建时 `.md` 会被自动转成 `.html`（或按 `cleanUrls` 去掉后缀），你不用管最终 URL 长什么样。

**不要写 `.html`**。开了 `cleanUrls` 之后，手写 `.html` 的链接会 404。

::: tip 为什么要写 .md
除了 VitePress，GitHub 网页也认 `.md` 链接——点进去是渲染后的页面。同一份文件，两边都能点。这是「内容可移植」的关键一环。
:::

### 锚点链接

跳到另一篇的某个小节：

```md
[什么是闭包](./2.closure.md#what)
[跳到「常见错误」](./2.closure.md#pitfalls)
```

锚点用你在标题后面写的 `{#what}`。如果没写显式锚点，就用标题文本（中文也行）：

```md
[跳到「什么时候用」](./2.closure.md#什么时候用)
```

::: warning 锚点必须是真实存在的
`ignoreDeadLinks: false` 会让构建检查每一个锚点。写错一个字，构建直接失败。这是好事，别去关它。
:::

### 外部链接

正常写就行，VitePress 会自动加 `target="_blank"`：

```md
[GitHub](https://github.com/xx-pple/FT-knowledge)
```

### 死链会怎样

构建失败，并告诉你哪个文件的哪一行指向了不存在的目标：

```
✖ building client + server bundles...
build error:
[vitepress] Dead link found: docs/frontend/4.async.md:12:1
```

按提示改，不要关 `ignoreDeadLinks`。

## 第 7 步：本地预览 {#preview}

```bash
npm run docs:dev
```

浏览器打开 `http://localhost:5173/FT-knowledge/`

注意末尾的 `/FT-knowledge/`，这是 `base` 前缀，不能省。直接访问 `http://localhost:5173` 会 404。

改文件会自动热更新，不用重启。左侧菜单、右侧目录都应该是最终效果。

**看完按 `Ctrl+C` 停止服务。**

## 第 8 步：提交上传 {#commit}

先做一次完整构建，确认没有死链和图片缺失：

```bash
npm run docs:build
```

::: warning 构建时如果报 dist 目录删不掉
说明 `docs:preview` 或某个进程还占用着 `docs/.vitepress/dist/`。先按 `Ctrl+C` 停掉它，再重新构建。
:::

构建通过后提交：

```bash
git add -A
git commit -m "新增：异步"
git push
```

三行，完事。

`git push` 之后 GitHub Actions 自动开始构建，通常 30–60 秒完成。

## 第 9 步：确认线上 {#verify}

打开 https://xx-pple.github.io/FT-knowledge/ ，确认四件事：

1. 新文章出现在左侧对应分组里
2. 点进去内容完整
3. 图片正常显示
4. 按 `Ctrl+K` 能搜到它

如果没出现，去 https://github.com/xx-pple/FT-knowledge/actions 看最近一次运行是不是红的，红色步骤名就是问题所在。

## 草稿与半成品 {#draft}

**没写完的东西放 `docs/drafts/`**：

```
docs/drafts/未完成的笔记.md
```

这个目录被 `srcExclude: ['drafts/**']` 排除，所以：

- 不会生成页面
- 不进侧边栏
- 不进搜索索引
- 不在 sitemap 里

写完后把文件挪进正式分类目录，就发布了。

::: danger 不要用 frontmatter 的 draft: true
VitePress **没有内置草稿机制**。写 `draft: true` 只会让它从侧边栏隐藏（前提是配了 `excludeFilesByFrontmatterFieldName`），但**页面照样会被构建、照样能通过 URL 访问、照样进搜索结果**。

真正的隔离只能靠目录。
:::

## 常见错误对照表 {#errors}

| 现象 | 原因 | 解决 |
|---|---|---|
| 构建报 `Dead link` | 链接漏 `.md` 或路径写错 | 按报错提示改 |
| 构建报找不到图片 | 相对路径不对，或图片没存进仓库 | 检查 `./` 开头、确认文件存在 |
| 线上图片裂，本地正常 | 文件名大小写不一致 | 全部改成小写 |
| 线上某页 404，本地正常 | 同上，Linux 区分大小写 | 同上 |
| 样式全丢，白底黑字 | `base` 不对 | 检查 `config.mts` 的 `base` |
| 新文章没进侧边栏 | 文件不在 `docs/` 下，或文件名以下划线开头 | 下划线开头的文件会被 `srcExclude` 排除 |
| 侧边栏顺序不对 | 没加数字前缀，或在多个文章间前缀重复 | 用 `1.`、`2.`、`3.` 递增 |
| 侧边栏显示的是文件名不是标题 | 文章没有 `#` 一级标题 | 补上一级标题 |
| 提示块显示成字面文本 | `:::` 后面没写类型，或没闭合 | 检查 `::: tip` 和 `:::` 成对 |
| 公式没渲染 | 独立公式的 `$$` 没单独占行 | `$$` 前后各留一个空行 |
| 图片超 100 MB 推不上去 | 单文件硬限制 | 压缩，或换图床 |
| 站点接近 1 GB 无法部署 | Pages 产物上限 | 压缩图片 |

## 一页速查卡 {#cheatsheet}

写作时贴在手边：

```md
---
title: 标题
tags: [标签]
---

# 标题

一句话定义，会被搜索摘要抓取。

## 小节 {#anchor}

正文。图片：![](./assets/x.png)
站内链接：[另一篇](./x.md)  锚点：[某节](./x.md#anchor)

::: tip
提示内容
:::

| 表头 | 表头 |
| --- | --- |
| 内容 | 内容 |
```

发布三步：

```bash
npm run docs:build    # 先确认无死链
git add -A && git commit -m "新增：xxx" && git push
```

**不要做的四件事**：文件名用中文或大写、图片放 `docs/public/`、链接写 `.html`、草稿靠 `draft: true` 隔离。
